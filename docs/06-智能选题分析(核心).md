# 阶段 06：智能选题分析（核心智能体）

> **全系统核心主线，必须重点实现。** 基于 Spring AI Tool Calling 编排 4 步流程，SSE 流式输出分析报告。这是整个项目的「灵魂」，请投入最多精力。

## 1. 目标
输入选题设想（如「基于计算机视觉的中药材识别系统」），智能体依次执行 4 个工具步骤，最终流式输出一份包含六维度（规则匹配、技术可行性、项目完整性、相似项目、选题风险、优化建议）的分析报告，全程**证据链可溯源，禁止预测获奖**。

## 2. 前置依赖
阶段 00、01、02、03、04、05（复用各模块检索能力）。

## 3. 验收标准（核心）
- [ ] `POST /api/v1/agent/analyze` 返回 SSE 流，前端 EventSource 可逐步展示。
- [ ] 流程固定为 4 步：Tool1 检索规则 → Tool2 匹配组别 → Tool3 检索往届 → Tool4 生成报告。
- [ ] 每个检索结果均带出处（来源/日期/页码）。
- [ ] 报告包含六个维度：规则匹配、技术可行性、项目完整性、相似项目、选题风险、优化建议。
- [ ] 报告与流中**绝不出现「获奖概率/获奖率」等预测性表述**。
- [ ] 支持指定竞赛（competitionId）或自动匹配。

## 4. 范围

### In Scope
- 4 个 Tool（Function）定义与注册。
- Agent 编排（Spring AI Tool Calling）。
- SSE 流式输出（SseEmitter / Flux）。
- 分析报告持久化（project + analysis_report + trace）。

### Out of Scope（严守边界）
- **禁止**生成获奖概率/获奖率预测。
- 不实现多智能体协同/复杂 Agent 框架（超出 4 步编排）。
- 不自动生成 PPT/视频（阶段 08/09）。

## 5. 数据模型

```sql
-- 项目/选题
CREATE TABLE project (
    id                  BIGSERIAL PRIMARY KEY,
    title               VARCHAR(255) NOT NULL,          -- 选题标题
    description         TEXT,                           -- 选题设想/描述
    direction           VARCHAR(128),                   -- 技术方向
    target_competition_id BIGINT REFERENCES competition(id),
    status              VARCHAR(16) DEFAULT 'DRAFT',    -- DRAFT/ANALYZED
    created_at          TIMESTAMPTZ DEFAULT now(),
    updated_at          TIMESTAMPTZ DEFAULT now()
);

-- 分析报告
CREATE TABLE analysis_report (
    id          BIGSERIAL PRIMARY KEY,
    project_id  BIGINT NOT NULL REFERENCES project(id),
    content     TEXT NOT NULL,                          -- Markdown 报告正文
    refs        JSONB,                                  -- 证据链
    created_at  TIMESTAMPTZ DEFAULT now()
);

-- 分析过程日志（供工作台/可解释性）
CREATE TABLE agent_trace (
    id          BIGSERIAL PRIMARY KEY,
    project_id  BIGINT NOT NULL REFERENCES project(id),
    step        INT NOT NULL,                           -- 1..4
    tool_name   VARCHAR(64) NOT NULL,
    input       TEXT,
    output      TEXT,
    started_at  TIMESTAMPTZ,
    ended_at    TIMESTAMPTZ
);
```

## 6. API 契约

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/agent/analyze` | 发起选题分析（SSE 流式） |
| GET | `/api/v1/agent/projects/{projectId}/report` | 获取历史报告 |
| GET | `/api/v1/agent/projects/{projectId}/trace` | 获取过程日志 |

SSE 事件类型（`data:` JSON）：
```json
// 1) 步骤开始
{ "type": "step_start", "step": 1, "tool": "searchRules", "message": "正在检索对应赛事及组别规则..." }
// 2) 检索证据
{ "type": "evidence", "step": 1, "data": { "source": "https://...", "pageNumber": 3, "sourceDate": "2025-12-01" } }
// 3) 步骤完成
{ "type": "step_end", "step": 1, "tool": "searchRules", "summary": "命中规则 3 条" }
// 4) 报告分片（流式）
{ "type": "delta", "content": "## 规则匹配\n..." }
// 5) 完成
{ "type": "done", "reportId": 1, "projectId": 1 }
// 6) 错误
{ "type": "error", "message": "..." }
```

请求：
```json
{ "projectId": 1, "title": "基于计算机视觉的中药材识别系统",
  "description": "……", "competitionId": 1 }
```

## 7. 核心流程（4 步编排）

```
输入设想 → Tool1 检索规则(RAG) → Tool2 匹配组别(LLM推理)
        → Tool3 检索往届作品(向量相似度) → Tool4 生成报告(LLM,含六维度)
```

- **Tool1 `searchRules`**：调用规则检索（复用阶段 03），返回与选题相关的赛事规则、组别要求，附出处。
- **Tool2 `matchGroup`**：LLM 依据 Tool1 结果与选题，推理应报组别（如本科组/研究生组）及匹配度，说明依据。
- **Tool3 `searchPastWorks`**：调用往届对比（复用阶段 05），返回相似作品与重合度。
- **Tool4 `generateReport`**：汇总前三步结果，LLM 生成 Markdown 报告，固定六维度：

| 分析维度 | 输出内容 |
|----------|----------|
| 规则匹配 | 是否符合所选组别的已知要求，具体依据是什么 |
| 技术可行性 | 需要的数据、算法、软硬件条件及主要难点 |
| 项目完整性 | 是否能够形成可演示的完整软件作品 |
| 相似项目 | 已收录作品中存在哪些接近的方向 |
| 选题风险 | 数据不足、开发周期过长、规则不符合等 |
| 优化建议 | 可以怎样调整功能和技术路线 |

并附证据链。**禁止获奖预测。**

## 9. 关键实现要点与约束
- 用 Spring AI `@Tool`/`@Description` 定义工具，`ChatClient` 绑定 `functions` 或 `toolCallbacks`。
- SSE：用 `SseEmitter`（同步栈）或 `Flux<ServerSentEvent>`（WebFlux），按 README 约定二选一并保持一致。
- 每步完成即推 `step_start/evidence/step_end`，报告内容分片推 `delta`。
- 报告持久化到 `analysis_report`，过程写 `agent_trace`（供阶段 11 工作台）。
- 系统提示词中**显式写入**「禁止输出获奖概率/获奖率；所有结论必须可溯源」。
- LLM 调用失败需捕获并推送 `error` 事件，不中断连接异常。
