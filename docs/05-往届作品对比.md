# 阶段 05：往届作品对比

> 通过向量相似度检索往届作品，分析选题/技术路线的重合度，为「创新性/可行性」评估提供依据（智能体 Step3 复用）。

## 1. 目标
输入选题描述或关键词，检索往届作品，返回相似作品列表及「主题重合度」「技术路线重合度」的量化/定性说明，供后续选题分析引用。

## 2. 前置依赖
阶段 00、02（往届作品作为资料入知识库）。

## 3. 验收标准
- [ ] 输入选题设想，返回 Top-K 相似往届作品。
- [ ] 每项给出重合度评估（主题/技术路线），并标注出处。
- [ ] 无相似结果时明确返回空，不编造。

## 4. 范围

### In Scope
- 往届作品的语义检索与相似度排序。
- 重合度评估（基于命中片段 + LLM 摘要）。
- 支持按竞赛/年份过滤。

### Out of Scope
- 不做抄袭判定/查重系统。
- 不生成完整对比报告（阶段 06 引用本模块结果）。

## 5. 数据模型
复用向量库与 `document`（往届作品文档可标记类型 `document_type = 'PAST_WORK'`）。
在 `document` 表新增列（迁移）：
```sql
ALTER TABLE document ADD COLUMN document_type VARCHAR(16) DEFAULT 'MATERIAL'; -- MATERIAL/PAST_WORK
ALTER TABLE document ADD COLUMN work_year VARCHAR(16);
```

## 6. API 契约

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/compare/past-works` | 往届作品相似检索 |

请求/响应：
```json
// 请求
{ "topic": "基于计算机视觉的中药材识别系统", "competitionId": 1, "topK": 5 }

// 响应 data
{
  "works": [
    { "documentId": 9, "title": "基于深度学习的植物识别系统",
      "workYear": "2024", "topicOverlap": "高", "techOverlap": "高",
      "overlapDesc": "均采用 CNN 图像分类，主题高度相似，建议差异化创新点",
      "source": "https://example.com/past.pdf", "sourceDate": "2024-06-01", "score": 0.89 }
  ]
}
```

## 7. 核心流程
1. 向量检索：topic → embedding → search（过滤 document_type=PAST_WORK、competitionId）。
2. 取 topK 命中片段。
3. 重合度评估：LLM 依据片段，从「主题」与「技术路线」两个维度给出高/中/低与一句话说明。
4. 组装返回（含出处）。

## 8. 文件结构
```
backend/.../compare/
├── dto/ PastWorkCompareRequest.java, PastWorkCompareResult.java
├── service/ PastWorkCompareService.java
└── controller/ PastWorkCompareController.java
```

## 9. 关键实现要点与约束
- 往届作品入库时标记 `document_type=PAST_WORK` 与 `work_year`。
- 重合度输出为「高/中/低」+ 说明，禁止预测获奖。
- 结果带出处（source/sourceDate）。
