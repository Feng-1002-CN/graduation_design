# 阶段 01：竞赛信息管理

> 竞赛/组别/规则的结构化数据底座，为检索、规则解读、选题分析提供可靠数据源。

## 1. 目标
实现竞赛信息（名称、主办方、时间、组别、官网、规则）的结构化维护，支持录入、查询、编辑、删除；每条记录强制携带**来源与发布日期**元数据，用于后续「禁用过期规则」。

## 2. 前置依赖
阶段 00（基础设施）。

## 3. 验收标准
- [ ] 可新增竞赛并录入 ≥3 类竞赛资料（如：计算机设计大赛、挑战杯、互联网+、蓝桥杯等）。
- [ ] 支持按名称/主办方/类别/时间范围筛选、分页查询。
- [ ] 组别与规则以结构化方式存储（含来源 URL、来源日期、发布日期）。
- [ ] 能标记规则/竞赛为「过期/停用」，检索与解读自动过滤。
- [ ] 删除为逻辑删除（软删除），不物理删库。

## 4. 范围

### In Scope
- 竞赛信息 CRUD、分页/筛选查询。
- 组别（Group）与规则（Rule）作为子实体管理。
- 来源与日期元数据强制校验。

### Out of Scope
- 不解析规则文件内容（那是阶段 02 知识库的职责）。
- 不做语义检索、不做推荐（阶段 03/04）。
- 不做爬虫自动采集（MVP 手动录入 + 可选粘贴）。

## 5. 数据模型

```sql
-- 竞赛
CREATE TABLE competition (
    id               BIGSERIAL PRIMARY KEY,
    name             VARCHAR(255) NOT NULL,            -- 竞赛名称
    organizer        VARCHAR(255),                     -- 主办方
    category         VARCHAR(64),                      -- 类别：软件/硬件/AI/综合
    level            VARCHAR(64),                      -- 级别：校级/省级/国家级/国际
    official_website VARCHAR(512),                     -- 官网
    register_start   DATE,                             -- 报名开始
    register_end     DATE,                             -- 报名截止
    contest_start    DATE,                             -- 比赛开始
    contest_end      DATE,                             -- 比赛结束
    description      TEXT,                             -- 简介
    source_url       VARCHAR(512) NOT NULL,            -- 来源（强制）
    source_date      DATE NOT NULL,                    -- 来源发布日期（强制）
    status           VARCHAR(16) DEFAULT 'ACTIVE',     -- ACTIVE / EXPIRED
    deleted          BOOLEAN DEFAULT FALSE,
    created_at       TIMESTAMPTZ DEFAULT now(),
    updated_at       TIMESTAMPTZ DEFAULT now()
);

-- 组别
CREATE TABLE competition_group (
    id             BIGSERIAL PRIMARY KEY,
    competition_id BIGINT NOT NULL REFERENCES competition(id),
    name           VARCHAR(128) NOT NULL,              -- 组别名：本科组/研究生组
    eligibility    TEXT,                               -- 参赛资格
    deleted        BOOLEAN DEFAULT FALSE
);

-- 规则
CREATE TABLE competition_rule (
    id             BIGSERIAL PRIMARY KEY,
    competition_id BIGINT NOT NULL REFERENCES competition(id),
    group_id       BIGINT REFERENCES competition_group(id), -- 可空=通用规则
    title          VARCHAR(255) NOT NULL,
    content        TEXT NOT NULL,                      -- 规则正文
    source_url     VARCHAR(512) NOT NULL,
    source_date    DATE NOT NULL,
    publish_date   DATE,                               -- 规则发布日期
    status         VARCHAR(16) DEFAULT 'ACTIVE',       -- ACTIVE / EXPIRED
    deleted        BOOLEAN DEFAULT FALSE,
    created_at     TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX idx_competition_name ON competition(name);
CREATE INDEX idx_rule_competition ON competition_rule(competition_id, status);
```

## 6. API 契约

统一前缀 `/api/v1/competitions`。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/competitions` | 新增竞赛（含组别/规则可选） |
| GET | `/api/v1/competitions` | 分页查询，支持 `name/organizer/category/level/status` 过滤 |
| GET | `/api/v1/competitions/{id}` | 详情（含组别、规则） |
| PUT | `/api/v1/competitions/{id}` | 更新 |
| DELETE | `/api/v1/competitions/{id}` | 软删除 |
| GET | `/api/v1/competitions/{id}/rules?activeOnly=true` | 查询有效规则 |
| POST | `/api/v1/competitions/{id}/rules` | 新增规则 |
| PUT | `/api/v1/competitions/rules/{ruleId}` | 更新规则 |
| GET | `/api/v1/competitions/groups/{groupId}` | 组别详情 |

新增竞赛请求示例：
```json
{
  "name": "中国大学生计算机设计大赛",
```

## 7. 核心流程
1. 校验必填：`name`、`sourceUrl`、`sourceDate` 非空；`sourceDate` 不得为未来日期（可告警）。
2. 保存竞赛主记录；级联保存组别与规则。
3. 查询时默认过滤 `deleted = false`；规则查询默认过滤 `status = ACTIVE` 及过期日期。
4. 「过期」判定：`contest_end < today` 或 `status = EXPIRED` → 标记，供下游过滤。

## 9. 关键实现要点与约束
- 实体使用 JPA，`@OneToMany(cascade = ALL)`；查询避免 N+1（`@EntityGraph` 或 DTO 投影）。
- 软删除统一在 Repository 层用 `@SQLDelete` 或自定义查询实现。
- 日期存储用 `LocalDate` / `TIMESTAMPTZ`，接口序列化 ISO-8601。
- 新增/更新必须保留 `sourceUrl`、`sourceDate`，缺失即拒绝（40001 错误码）。
